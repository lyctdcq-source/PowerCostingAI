# 架构与边界

Windows WebView2 桌面窗口承载本地前端，通过 127.0.0.1:8766 访问 Python 工作流服务。主窗口管理服务生命周期；菜单调用固定前端动作。在线模型配置只保存在进程内存。

数据清洗、物资匹配与数量评审的业务逻辑以流程技能形式维护（pipeline_skills.py，模板在 skill_templates/pipeline），LLM_service.py 只负责模型调用、日志与结果写出。三个业务工作区覆盖数量核对、信息价比较、图纸提资和价格库版本管理；知识库保留出处、审核与版本；技能可根据指令生成代码差异并验证后应用。目录清洗与中间检查点允许用户干预。

物资智能评审的对话由智能体循环（agent.py）处理：模型提出工具调用，平台校验参数后执行，结果交回模型，直到给出回答，每一步显示在对话的执行过程里。工具统一用 JSON Schema 描述参数并注册到同一张表（与 MCP 工具的 inputSchema、OpenAI 兼容接口的 tools 一致），以后接入的 MCP 工具注册到同一张表即可；模型优先用原生工具调用（llm_client.request_chat），接口不接受时改用 JSON 动作协议。发给模型的对话和工具结果先在本机脱敏，模型给出的工具参数和回答再换回原名；回答只保留工具结果中出现过的条目行号、联网来源和知识库条目。只读工具：查匹配结果、按编号取条目、项目概况与受控查询、知识库检索、联网检索、匹配方法说明。写入类工具（改结论、确认复核、改配对、撤销修改）执行前经过与 Claude Code 钩子对应的检查（before）：先调用流程技能“评审·修改校验”（edit_check，业务规则全在技能里，可修改、有版本，但每次保存须通过平台固定的修改校验底线测试），再按权限模式在对话里显示批准卡片（每次询问 / 本次对话都允许；技能可要求某类修改每次都须批准）。批准前循环暂停，用户选择后继续。每次修改先存检查点、记修改编号，最近一次可撤销；改配对只把新形成的配对和单侧条目标为待复核，其余行保留原结论和行号。平台本身只保留不含业务判断的底线：参数格式、条目存在、写前存检查点、执行中不接受其他写入。文档工具（导出 Excel、生成 Word 报告、查文件、打开文档）把文件写入数据目录 outputs 并登记到本次评审的 documents，回答带文件卡片；右侧“文档”页签复用 Excel 分页查看接口，Word 由 /api/docs/preview 按正文顺序转为标题、段落和表格后在前端渲染。“资料清洗”“继续”“价格阈值”等固定指令和修改技能仍按原规则处理，不经过智能体。

土石方数智化算量的工程量、造价与寻优在前端计算引擎完成（three.js 本地发布，不访问外网）；后端 earthwork.py 提供已清洗的模型数据、规则质检、方案存档和比选报告。模型只把用户的话转成白名单内的动作并解读计算结果，动作经取值范围校验后由引擎执行；发给模型的只有工程量汇总与统计量，不含坐标。资料清洗（布置图与勘察报告 → 三维建模基础数据 DXF、勘探点平面位置图 DXF、钻孔分层 CSV）全程本机规则：PDF 按图层提取矢量、钻孔坐标配准、等高线由高程点和相邻关系定高程，成果写入资料文件夹下的“土石方清洗成果”。三维建模（earthwork_model.py）由清洗成果构三角网、重采样格网 DEM、按钻孔插值地层界面，生成前端引擎用的 model.json，同样在本机完成。

当前仍为单用户、单活动任务。信息价口径对齐使用规则，尚未实现自动抓取公开信息价；DWG 需转 PDF；视觉一次最多识别 PDF 前三页；Word/Excel 修改是有限操作集，不等同 Office 全功能编辑。规范知识需要专业人员导入并审核。尚未进行大型工程验收、并发压力测试、安装包签名或自动更新。
